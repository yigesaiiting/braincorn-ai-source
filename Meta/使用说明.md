# 使用说明

这是一份给 Braincorn vault 使用者的简明操作手册。

## 这个 vault 是什么

这个 vault 不是单纯的笔记仓库，而是一个知识处理系统：

- `Inbox/`：临时收集箱
- `Raw/`：原始资料层
- `Wiki/`：可复用知识层
- `Projects/`：项目推进层
- `Resolutions/`：决策与复盘层
- `Outputs/`：输出沉淀层
- `Meta/`：规则、模板、流程、导航层

## 你应该把内容放到哪里

### 1. 还没整理的想法

放到 `Inbox/`。

适合：

- 临时灵感
- 还没想清楚的片段
- 需要先判断归属的内容

### 2. 原始资料

放到 `Raw/`。

适合：

- 文章原文
- 截图
- 网页整理前材料
- 访谈记录
- 项目原始备忘

原则：

- 默认不改写
- 先收集，再编译

### 3. 整理后的知识

放到 `Wiki/`。

适合：

- 概念
- 公司
- 人物
- Playbook
- 产品

要求：

- 尽量有 YAML frontmatter
- 尽量带内部链接
- 能复用、能检索、能迭代

### 4. 正在推进的任务

放到 `Projects/`。

适合：

- 当前在做的项目
- 还没结束的战役
- 需要持续推进的问题

### 5. 关键判断和复盘

放到 `Resolutions/`。

适合：

- 职业选择
- 投资判断
- 产品判断
- 阶段性复盘

### 6. 阶段性输出

放到 `Outputs/`。

适合：

- 研究报告
- PRD
- 文案
- 周报
- 演示提纲

## 推荐使用流程

最常见的流程是：

1. 先把资料扔进 `Inbox/` 或 `Raw/`
2. 再让 Codex 帮你编译成 `Wiki/`、`Projects/`、`Resolutions/` 或 `Outputs/`
3. 最后把新判断回流到相关 wiki 页面

可以理解为：

`收集 → 整理 → 沉淀 → 输出 → 回流`

## 简单原则

1. 不确定就先放 Raw 或 Inbox。
2. 原始资料不要随便改。
3. 整理后的内容要尽量互相链接。
4. 每次输出后尽量回流到相关页面。
